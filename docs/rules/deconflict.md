# 解耦与上游同步规则

1. 这是一个开源项目，我们拉取了代码进行二次开发。
2. 后续会从开源项目同步新增代码，因此我们开发的代码需要尽量解耦，尽量减少后续同步代码时的代码冲突。
3. 解耦的同时需要确保后续同步上游代码时避免错过上游更新的最新代码。可以通过在 `docs/CUSTOM_CHANGES.md` 中添加相关说明，后续同步代码时通过检查该文件来避免该问题。
4. 如果后续存在需要重点关注的自定义逻辑（例如专用 DTO、脱敏、allowlist、安全搜索、性能风险等），应优先补充到 `docs/UPSTREAM_SYNC_CHECKLIST.md`，并在同步上游代码时先检查该文件，再对照 `docs/CUSTOM_CHANGES.md`。

## 操作规范

### 新增功能

- 尽量新建文件，避免修改上游已有文件。
- 如需修改上游文件，改动范围尽量小，并在 `docs/CUSTOM_CHANGES.md` 记录该修改的位置与目的。
- 新建的控制器、模型、服务文件不受上游影响，可自由扩展。

### 上游同步流程

1. 同步前先阅读 `docs/UPSTREAM_SYNC_CHECKLIST.md`，确认高风险点。
2. 参照 `docs/CUSTOM_CHANGES.md`，逐条检查每个修改点是否受上游改动影响。
3. 如发生冲突，以"保留我们的自定义逻辑"为原则解决，同时吸收上游的功能更新。
4. 同步完成后更新 `docs/CUSTOM_CHANGES.md` 中的"上次同步"版本记录。

### 禁止行为

- 禁止在未记录的情况下修改上游核心文件（`model/main.go`、`router/api-router.go`、`middleware/auth.go` 等）。
- 禁止将临时调试文件提交到仓库（如 `*.recovery.bak`、根目录的纯数字命名 .md 文件）。
