# Code Review 规则（git 暂存区）

> 目标：对 **git 暂存区（staged）** 的改动做一次完整审阅，优先识别回归、稳定性与性能风险；同时遵守项目的"解耦/减冲突"原则。

## 审阅清单

- [ ] 覆盖面：review 覆盖所有暂存区文件（后端/前端/脚本/文档）
- [ ] 健壮性：边界条件、空值、并发安全、错误处理、超时与资源释放
- [ ] 回归风险：是否改变现有逻辑/接口/默认值/DB 字段；是否影响旧配置兼容
- [ ] 性能：是否引入额外 DB 查询、锁争用、goroutine 堆积、内存增长；是否有清理/限流/降级策略
- [ ] 安全：输入校验、SSRF/注入、敏感信息泄露、权限校验
- [ ] 变更最小化：与本次功能无关的改动（format/import/依赖升级/重构）是否应拆分或回退
- [ ] 记录同步：确认 `docs/CUSTOM_CHANGES.md` 已同步本次修改信息
- [ ] 解耦规范：确认符合 `docs/rules/deconflict.md` 的要求（减少与上游冲突，避免遗漏上游更新）

## 输出要求（给审阅结果文档）

- 改动文件清单（按模块分组）
- ✅ 已确认项（通过/需关注）
- ⚠️ 需要关注的问题（按严重程度排序）
  - 必须包含：**位置**、**问题**、**风险**、**建议**
- **如果发现需要调整的地方，先提示我，不要直接动代码。**
